= X Compiler: A Self-Hosting Dependently Typed Language

This project implements a self-hosting compiler for a dependently typed
language (file extension `.x`) following the exact architecture of
https://github.com/blynn/compiler[Ben Lynn's Compiler Quest].

== Architecture Overview

The bootstrapping chain follows an *RPG progression* model where each
compiler generation adds new features while being compilable by the previous
generation.

=== Layer 0: The C Virtual Machine

`vm.c`:: The *only* file written in C (~650 lines). A lazy graph-reduction
machine for SK(I) combinators with mark-and-sweep garbage collection.
It contains three hard-coded parser generators written in raw combinator
code:
- `parenthetically` — parenthesis parser
- `exponentially` — applicative parser combinators
- `practically` — bracket abstraction parser (lambda `\x -> expr` to combinators)

`rts.c`:: C runtime system providing `putchar`, `getchar`, `getArgCount`,
`getArgChar` for compiled executables.

=== Layer 1: The Singularity

`singularity`:: Generation 0. A parser combinator library executed by `vm.c`.
Parses a minimal lambda calculus with:
- Variables (lowercase letters)
- Lambda `\x -> expr`
- Function definitions `f x = expr;`
- Comments `-- comment`
- Predefined combinators `@K`, `@I`, `@Y`, `@S`, `@B`, `@C`, `@T`, `@R`

`singularity.boot`:: Pre-compiled accelerator for the singularity parser.
Generated by `bootsingularity.sh` (sed pipeline that removes comments,
renames variables, and compresses lambdas).

=== Layer 2–6: The RPG Upgrade Chain

[cols="1,3"]
|===
| File | Feature Added
| `semantically` | Minimal type system
| `stringy` | String and list primitives
| `binary` | Binary operations (`&&`, `||`, `not`, `ife`)
| `algebraically` | Algebraic data types (`data`, `case`, Scott encoding)
| `parity.x` | Operator precedence declarations (`infix`, `infixl`, `infixr`)
| `fixity.x` | Fixity resolution for operators
| `typically.x` | Implicit arguments `{a : Type}`
| `classy.x` | Interface/implementation records (typeclasses)
| `barely.x` | Raw combinator memory dump output
| `effectively.x` | `IO` monad and `foreign import ccall`
| `lonely.x` | Standalone `main :: IO ()` compiler
| `virtually.x` | Bundled RTS (no manual `cat rts.c`)
|===

=== Layer 7: The Modern Compiler (`inn/`)

The final modular compiler written in the bootstrapped dialect:

| `inn/Base.x` | Standard library: Functor, Applicative, Monad, Monoid, Map, arbitrary-precision integers
| `inn/Ast.x` | Abstract syntax tree: Pi, Sigma, Eq, Refl, Data, Case, Pattern
| `inn/Parser.x` | Idris-style syntax parser (`\x => e`, `(x : A) -> B`, `do`, `case`)
| `inn/Typer.x` | Bidirectional type checker with WHNF evaluation, substitution, and convertibility
| `inn/Kiselyov.x` | Type erasure + optimal bracket abstraction to SK(I) combinators
| `inn/RTS.x` | Code generation: C backend, WebAssembly C backend, raw dump
| `inn/Precisely.x` | Main driver: parse → typecheck → compile → output

== Language Syntax (Idris-style)

[source,idris]
----
-- Dependent function type
id : {a : Type} -> a -> a
id x = x

-- Algebraic data type
data Nat = Z | S Nat

add : Nat -> Nat -> Nat
add Z y = y
add (S x) y = S (add x y)

-- Propositional equality
data (=) : {a : Type} -> a -> a -> Type where
  Refl : {a : Type} -> {x : a} -> x = x

-- Substitution from equality
subst : {a : Type} -> {x : a} -> {y : a}
      -> x = y -> (P : a -> Type) -> P x -> P y
subst Refl P px = px

-- Length-indexed vectors
data Vect : Nat -> Type -> Type where
  Nil  : Vect Z a
  Cons : (n : Nat) -> a -> Vect n a -> Vect (S n) a

head : (n : Nat) -> (a : Type) -> Vect (S n) a -> a
head n a (Cons _ x _) = x
----

== Type System

- *Pi types*: `(x : A) -> B x` — dependent functions
- *Sigma types*: `(x : A ** B)` — dependent pairs
- *Propositional equality*: `x = y` with `Refl`
- *Pattern matching* with unification-driven type checking
- *Type-in-Type* for bootstrapping simplicity (Universe = Term)
- *Full type erasure* before code generation

== Building

Only a C compiler is required to start:

[source,bash]
----
make all         # Build the VM
make test        # Run combinator engine tests
make singularity.boot   # Generate the bootstrap accelerator
make bootstrap   # Run the full RPG chain
----

To build the modern compiler:

[source,bash]
----
make modern      # Produces `precisely` executable
./precisely check test/simple.x
./precisely compile test/simple.x > simple.c
----

== Web IDE / WebAssembly

A browser-based interactive compiler is included in `web/`:

[source,bash]
----
# Open directly in browser
open web/index.html

# Or deploy to any static host
make deploy
----

The web IDE includes:
- A JavaScript combinator VM
- An Idris-style parser
- A bracket abstraction compiler
- Example programs (Nat, Vect, Equality)
- WebAssembly text (WAT) generation

=== WebAssembly Backend

The compiler supports three output modes:

1. *C backend* (`make compile-foo`): Traditional C code + rts.c
2. *WASM C backend* (`./precisely wasm foo.x`): C-for-WASM using
   `clang --target=wasm32 -ffreestanding`
3. *WAT output* (web IDE): WebAssembly text format for browser embedding

== Survival Game

Like the original Compiler Quest, this is a *survival game*: at any point,
you can rebuild everything from only `vm.c` and a C compiler. Each generation
is a single file that compiles the next.
